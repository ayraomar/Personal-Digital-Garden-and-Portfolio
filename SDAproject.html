Our project is to select a real-world system, without any limitations in terms of skill or personal aptitude as we are not required to write the code, only to design the system.

Phase 1

To begin our project, we had to make an SRS document. This meant that we had to introduce our problem, propose a solution, and explain where it would be relevant.

Additionally, we were required to submit a Context Diagram and a Use-Case Diagram to support our solution.

I'm working on this project in a group of 4, so we divided this work amongst outselves based on preference and first-come first-serve.

We unanimously decided to choose the problem that comes with research. With the rise of academic publications, it's difficult to find exactly what it is you're looking for. Plus, the jargon and needlessly complicated wording is discouraging to aspiring researchers and students, preventing them from reaping the benefits of academic works.

Introducing the problem and explaining it further was my job.

My group member, Duaa, took on explaining our proposed solution. We decided that a Research Copilot would be an optimal solution to our problem. This digital assistant aims to provide users with a dynamic space that pulls out the information you need from an article without you needing to go through it and manually dissect it or beg it to give you the answers it seems to so closely guard. It also has the functionality of finding contradictory and complimentary research in order to provide plenty of sources. Finally, there's a built-in chatbot that can explain concepts, answer questions, and simplify complicated terminology. All in all, Duaa did an excellent job detailing the solution we'd come up with.

Asra worked on defining the scope of the project. She listed pre-existing solutions, the inclusions, and the exclusions.

Finally, Ruhab explained the objectives and provided the Context and Use-Case Diagrams for our model.

Phase 3

Phase 3 consisted of the hardware and software requirements of our project and was handled by Ruhab alone.

Software Requirements:

1. Server-Side & Backend Architecure

For the server-side architecture, we selected an Ubuntu-based environment using a FastAPI and React stack. This design prioritizes Python’s extensive library ecosystem for AI processing, leveraging Anthropic Claude or OpenAI GPT-4 APIs for the chatbot interface and PyMuPDF for document parsing. To power the discovery features, the system integrates the Semantic Scholar API, providing access to a database of over 200 million papers for citation mapping and literature discovery.

2. Client-Side & User Environment

On the client side, the project is designed as a lightweight, zero-install web application compatible with any modern browser and Android 10+. The requirements focus on standard web technologies like JavaScript and Browser Storage, ensuring that user preferences and session states are managed locally without extra software. This architecture ensures the system remains accessible across devices while offloading all heavy computational tasks to the cloud-hosted backend.


Hardware Requirements:

1. Server-Side & Backend Architecure

The server-side hardware is designed to handle high-concurrency tasks like NLP processing and graph generation. The specifications call for an 8-core CPU and 32GB of RAM to ensure smooth performance when parsing multiple PDFs and managing API data streams simultaneously. Additionally, a 1TB SSD is required to provide high-speed storage for user data, analytical history, and the system's core software, supported by a stable, high-bandwidth internet connection for constant communication with external AI models.

2. Client-Side & User Environment

On the client side, the requirements are kept accessible to ensure the tool runs on standard consumer devices. A dual-core processor and 4GB of RAM are the minimum needed to render the web interface, though a quad-core system with 8GB of RAM is recommended for a smoother experience when interacting with complex citation graphs. Since the application is entirely cloud-based, a consistent internet connection is essential, along with basic peripherals for document navigation and viewing.
